# TMOS v0.2 Deployment Guide

Status: Released
Version: 0.2.0
Date: 2026-07-17

## 1. Prerequisites

- Linux host
- Docker and Docker Compose plugin
- Node.js 20+
- npm
- Network access to provider endpoints (for enabled providers)

## 2. Infrastructure Deployment (PostgreSQL)

From repository root:

```bash
docker compose up -d postgres
docker compose ps
```

Verify database readiness:

```bash
docker compose exec postgres pg_isready -U postgres -d tmos
```

## 3. Backend Configuration

Create backend env file from example:

```bash
cd backend
cp .env.example .env
```

Required variables:

- `TMOS_DATABASE_URL`
- `TMOS_JWT_SECRET`
- `TMOS_ADMIN_USER`
- `TMOS_ADMIN_PASS`

Recommended production values:

- `NODE_ENV=production`
- `TMOS_DATABASE_REQUIRED=true`
- `TMOS_ENFORCE_VPN_POLICY_ON_STARTUP=true`

## 4. Database Migration

```bash
cd backend
npm ci
TMOS_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/tmos' npm run migrate
```

## 5. Start Backend

```bash
cd backend
TMOS_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/tmos' npm run start
```

Startup gates:

- Database configuration/connectivity must be valid.
- RBAC protected-route mapping check must pass.
- VPN policy gate must pass unless emergency override is enabled.

## 6. Start Frontend (Optional for local UI)

```bash
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173
```

## 7. Health Verification

Backend:

```bash
curl -i http://127.0.0.1:8081/
curl -s http://127.0.0.1:8081/api/v1/health
```

Expected:

- HTTP 200
- success envelope
- database status present in health response

## 8. Post-Deploy RBAC Verification

- Authenticate as each default role.
- Verify role-bound allow/deny behavior.
- Confirm deny responses return `403 RBAC_DENIED`.
- Confirm `authz.decision` entries in `audit_logs`.

## 9. Rollback Strategy

- Keep previous backend release artifact.
- Roll back app process to previous release.
- If schema rollback is required, restore from backup (see backup/restore runbook).
