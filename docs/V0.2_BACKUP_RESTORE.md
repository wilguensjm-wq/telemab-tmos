# TMOS v0.2 Backup and Restore Procedures

Status: Released
Version: 0.2.0
Date: 2026-07-17

## 1. Scope

This runbook covers PostgreSQL backup and restore for TMOS backend data.

Key data categories:
- Users and sessions
- RBAC roles/permissions/user assignments
- Audit logs
- Events
- Provider state
- Runtime config entries

## 2. Backup Strategy

- Daily logical backup with `pg_dump` custom format.
- Keep at least 7 daily backups and 4 weekly backups.
- Store off-host copy for disaster recovery.

## 3. Backup Command

From repository root:

```bash
mkdir -p database/backups
pg_dump \
  --format=custom \
  --no-owner \
  --no-privileges \
  --dbname='postgres://postgres:postgres@127.0.0.1:5432/tmos' \
  --file="database/backups/tmos_v0.2_$(date +%F_%H%M%S).dump"
```

Validation:

```bash
pg_restore --list database/backups/<backup-file>.dump | head
```

## 4. Point-in-Time Considerations

Logical backups are transaction-consistent at dump time.
If strict PITR is required, configure WAL archiving separately.

## 5. Restore Procedure (Full)

1. Stop application writes.

```bash
# stop backend process/service
```

2. Recreate clean database (if full replacement is needed).

```bash
dropdb --if-exists --username=postgres tmos
createdb --username=postgres tmos
```

3. Restore dump.

```bash
pg_restore \
  --clean \
  --if-exists \
  --no-owner \
  --no-privileges \
  --dbname='postgres://postgres:postgres@127.0.0.1:5432/tmos' \
  database/backups/<backup-file>.dump
```

4. Start backend and run health checks.

```bash
cd backend
TMOS_DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/tmos' npm run start
curl -s http://127.0.0.1:8081/api/v1/health
```

## 6. Post-Restore Verification Checklist

- Login works for expected users.
- RBAC mappings exist and authorization behaves correctly.
- Audit/event tables are readable.
- Provider state loads without errors.
- Startup route-mapping guard passes.

## 7. RBAC-Specific Validation SQL

```sql
SELECT role_key, COUNT(*) AS permission_count
FROM role_permissions
GROUP BY role_key
ORDER BY role_key;

SELECT u.username, ur.role_key
FROM user_roles ur
JOIN users u ON u.id = ur.user_id
ORDER BY u.username, ur.role_key;
```

## 8. Recovery Time and Recovery Point Targets

- Target RTO: 30 minutes
- Target RPO: 24 hours (daily logical backup baseline)
